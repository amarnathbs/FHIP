# A1.2 — Page-Pattern Catalogue

Ten standard page patterns, each reusing Wave 5's existing result-state (`ok`/`suppressed`/`unavailable`/error, Standard §8) and task-help (`AdminTaskHelp.tsx`/`lib/admin/taskHelp.ts`) components rather than inventing new ones. Each pattern names its current exemplar(s) so a future implementer copies working code, not a fresh design.

| # | Pattern | Purpose | Current exemplar(s) | Required states |
|---|---|---|---|---|
| 1 | List/search | Browse and filter a collection | `admin/resources/content/page.tsx`, `admin/resources/videos/page.tsx` | Loading, populated, empty (genuinely zero rows), filtered-to-zero, error |
| 2 | Work queue | A filtered list the caller is expected to act on, framed around "what needs doing" | `admin/resources/content/{drafts,review,scheduled,published,review-due,archived}/page.tsx` | Same as List/search, plus "nothing needs your attention" (distinct copy from "no results for your filter") |
| 3 | Create/edit | A form producing or mutating one record | `admin/resources/content/new`, `.../[id]/edit` | Untouched-empty (no premature validation, D5-6's own disclosed gap notwithstanding), dirty-unsaved, saving, saved, validation error, conflict (D5-8's own disclosed gap — no `expectedUpdatedAt` contract exists yet) |
| 4 | Review/approval | A record moves through a state machine with distinct actor roles at each step | `WorkflowPanel.tsx` (embedded in `.../[id]/edit`), `admin/benchmarks` (source approve/suspend/reinstate) | Current state, allowed-next-states for this caller (never all states), transition-in-flight, transition-succeeded, transition-rejected (with reason) |
| 5 | Detail + audit history | A single record's current state plus its change history | `resource_workflow_history` rendered inline on content edit pages; `admin/benchmarks` update-runs tab | Current state, history list (paginated), empty history (genuinely new record), history-load error distinct from record-load error |
| 6 | Import/validation | Bulk upload with structured validation feedback | `admin/recommendations` CSV upload (4 file types) | Pre-upload, validating, per-row validation results (accepted/rejected with reason), all-or-nothing commit confirmation, partial-failure is never silently accepted (Standard §13 — an import either fully commits or fully rejects) |
| 7 | Reorder | Drag/priority-based ordering of a set | `admin/resources/related/page.tsx` | Current order, in-flight reorder (optimistic UI permitted only if the server call is itself atomic — `admin_reorder_related_content` is), reorder-failed (reverts to last-confirmed order, never a partial permutation) |
| 8 | Monitoring | Read-only operational/aggregate view, no mutation | `admin/benchmarks` update-runs/audit tab; future ADM-25 (AI cost/usage), ADM-36 (FDH operations) | `ok`, `suppressed` (fixed label, Standard §8), `unavailable`, refresh/staleness indicator where the metric has a meaningful "as of" time (Standard §12) |
| 9 | Unavailable state | An honest, reachable page for a capability-gated but not-yet-built feature | `admin/resources/analytics/page.tsx` (ADM-19) | Exactly one state: a plain notice that the feature is not yet available — no figure, no chart, no fabricated data of any kind (verified today by a test asserting the rendered text contains no digit) |
| 10 | Privacy-restricted support workflow | A time-limited, consented, purpose-bound access flow to sensitive data | **Does not exist yet** — `A1_14` is this pattern's full design (grant request, consent capture where applicable, active-access indicator, automatic expiry, immutable audit, no raw-document download without separate explicit authorisation) | Not-granted, grant-pending, active (with a visible countdown/expiry indicator), expired, revoked, denied |

## Cross-cutting rules for every pattern

- **Result-state semantics (Standard §8)** apply identically across all 10 patterns: `ok` / `suppressed` / `unavailable` are always distinguishable from each other and from an outright request failure.
- **No pattern renders a fabricated zero.** A List/search pattern with zero rows because of a fetch error must show the error, not an empty list.
- **Every pattern that mutates (3, 4, 6, 7, 10) re-derives its own authorization server-side** on both the page route and the API route, independent of which nav group led the caller there (Standard §4).
- **Pattern 10 does not exist in the current codebase** — it is the one genuinely new pattern this catalogue proposes, because no Admin surface today needs consented, time-limited access to sensitive data. It is included now so `A1_14`'s design and any future FDH-13 Wave F implementation start from an agreed page shape rather than inventing one under implementation pressure.
