## What was built, finding by finding

### F19 and F20: one derived net, no Difference
Root cause: phase 1 fixed the family view and the SMSF card but left the SMSF report, its CSV and its API bundle on the old "Summary balance / Detailed net / Variance" trio, and the card printed the migration 0084 note ("Backfilled by migration 0084 ...") as if the user had written it.
Fix: `smsfReportData.ts` now returns `position {mode, net}` read from the one database function `smsf_fund_counted_net` (no `reconciliation`); the panel and CSV show one net; `lib/engines/smsf/smsfNotes.ts` hides system-written notes. The mode-switch preview keeps its variance because that is a different, confirmation-gated concept.
Tests: `wpCSmsfDerivedNetOracle.test.ts` (13): one hand oracle, assets 475,000 + 3,000 + 25,000, liability 370,000, net 133,000, read dollar for dollar by the loader, the family block (family 1,007,441), the report bundle, the CSV, with a leftover typed 138,000 changing nothing, a net-only 138,000 proving the oracle can fail, and source contracts that no screen contains Difference, Reconciliation, Summary balance or Variance. Sabotage: with the four source files restored to the old version, 5 named tests fail. The database half is in `wpCEntityFinancePglite.test.ts` (derived net 133,000, the Retirement mirror and `smsf_fund_counted_net`). `smsfPnlCashFlowExport.test.ts` was updated deliberately (the two tests that asserted the old variance were replaced).
Forecast and personal figures: by the standing PO decision of 16-10-2026 the personal basis excludes the SMSF fund row (Dashboard, Retirement card, forecast opening balances). The SMSF is counted once, at its derived net, in the family level only. This was not changed.

### F21: SMSF Add liability never goes to the personal register
Root cause: phase 1 gave the fund its own liabilities table but the form was thinner than the personal one, and the personal Liabilities page still offered Owner "SMSF" and the catalogue item "SMSF Property Loan / LRBA" (the PO's second attempt, screenshots 29 to 31, created a PERSONAL liability tagged SMSF).
Fix: migration 0295 adds rate type, fixed-rate expiry, masked account reference (the same masking rule as the personal register, reusing WP-E's `maskedIdentifier.ts`), due date and `smsf_holding_id` (the property the loan funds, descriptive only, a trigger allows only a property asset of the same fund and the same household). The form carries all of them. `lib/services/entityOwnerGuard.ts` refuses an entity owner (smsf, company, family_trust) on a NEW row or a change of owner TO one, on personal Liabilities, Income and Expenses (coded 422 `ENTITY_OWNER_USE_ENTITIES`, plain wording); an existing entity-tagged row stays editable (the grid saves by POST upsert, so the check asks the database only when the request carries an entity owner). The three grids hide the owner from new selection, and personal Liabilities no longer offers the SMSF catalogue item (saved rows under it stay visible). Fund liabilities are in the fund net and in no personal figure or ratio (structural).
Tests: `wpCEntityOwnerRoutes.test.ts` (14, with a sabotage run: guard removed, 7 named failures), `wpCEntitySeparation.test.ts` (10: no personal engine or read model names an entity table), `wpCEntityFinancePglite.test.ts` (canonical fields, the 9-digit account number refused, property link refused for a cash asset and for another household's asset, two-user RLS), `wpCEntitiesWorkspace.test.ts`.
Note for WP-E (F24): the ordinary personal-loan edit failure is theirs. The PO's error in screenshot 30 is that masked-identifier rule, which WP-E fixed on main; the SMSF form now shares the same rule and wording.

### F22: SMSF income, rent needs an amount and a frequency
Root cause: SMSF income was a personal Income row tagged SMSF, and the holding form only offered a dropdown of such rows ("Linked Rental Income"), with no way to state the rent.
Fix: migration 0296 `entity_income_items` (rent, interest, dividends, distributions, trading revenue, other), scoped to one entity (SMSF fund or Company, Family Trust, HUF), with `user_id`, `entity_id`, country, currency, source (provenance). Rent needs an amount above zero and a frequency (database check and form), may be tied to its property, and a partial unique index allows ONE active rent record per property, so a flow is never in two places. The holding form no longer creates links to personal records; a property still tied the earlier way keeps the link and says so. A legacy personal income row tagged SMSF still counts in the fund's figures until moved, is listed, and `smsf_entity_move_personal_cash_flow` moves it preview-first in one transaction (the personal row is retired, a rent move takes over the property link).
Tests: `wpCEntityFinancePglite.test.ts` (zero rent refused, one rent per property, legacy link refusal, move preview changes nothing, apply retires the personal row, counted once, cross-household move refused), `wpCEntityCashFlow.test.ts`, `wpCEntitiesWorkspace.test.ts`.

### F23: SMSF expenses and the bank statement upload
Fix: `entity_expense_items` (migration 0296) with no loan repayment type (principal is cash flow and is derived from the fund liabilities; `computeEntityCashFlow` carries estimated interest in the operating result and the full repayment once in the cash flow, oracle: income 3,100, expenses 50, interest 1,911.67, principal 488.33, net operating 1,138.33, net cash flow 650; raising the repayment moves the cash flow by exactly the extra repayment and leaves the operating result alone). The SMSF card has Income and expenses and a Premium "Upload a bank statement" entry that REUSES the one `BankStatementImportPanel` with the owner fixed to the fund (new prop `fixedOwner`): the same Financial Data Hub lifecycle, owner-before-upload contract, Premium admission and malware gate, nothing re-implemented. Approved lines on SMSF-owned accounts feed the SMSF cash flow ONLY through `lib/read-models/smsfBankActuals.ts` (a test proves every line of the ledger is either a household line or a fund line, never both). Actuals are shown beside, never added to, the recurring figures.
Tests: `wpCEntityCashFlow.test.ts` (20), PGlite (principal is not an expense type, legacy loan-repayment expense refused on move), route tests (entity scoped, 404 for another household, retire not delete).
DEV certification of a real CSV and PDF upload: NOT PERFORMED. Production uploads stay gated by the malware, schema and readiness programme: this adds no switch and enables nothing.

### F23b: Company, Family Trust and HUF at entity level
Root cause: `/companies` stored a label and a value per line, hard-deleted, default mode "net value", mode changeable by a bare PATCH, no income or expenses, no provenance, no audit.
Fix: migration 0297 adds type, as-at date, lender, rate, repayment, country, source and `is_active` to the two line tables; the either-or rule in the database for company, family_trust and huf (an itemised entity cannot carry a typed net, a net-value-only entity cannot hold active lines, the mode changes only through `business_entity_switch_mode`, preview first, history in `entity_figure_mode_log`); audit triggers writing the append-only `entity_change_log` for every entity line (also the SMSF holdings and liabilities). The page is now an entity workspace (`components/entities/*`): how it is recorded, assets and liabilities with a derived read-only net, income, expenses, the monthly picture, history, archive. New entities default to itemised. HUF stays India only (the existing route gate and trigger). The PATCH schema no longer accepts the mode.
Tests: PGlite (the rule and its negative controls, switch preview and apply, history, kind mismatch, HUF gate, two-user RLS on every new table, append-only log, account deletion cascade), `wpCEntitiesWorkspace.test.ts`.

### F28: Dashboard entity section
`NetWorthLevelsPanel` now shows for every entity: name, the entity's OWN assets, liabilities and net economic value (at 100 percent), then what is counted in the family figure and why (SMSF, Trust and HUF in full, Company by share). A net-value-only entity says "Recorded as a net value only" instead of inventing assets and liabilities (`NetWorthEntityBlock.recording`). `wpCEntityDashboardSection.test.ts` (13): SMSF 503,000 / 370,000 / 133,000, Trust and HUF 1,000,000 / 400,000 / 600,000 in full, Company 40 percent of 250,000 = 100,000, an underwater trust -50,000 never clamped, family 2,257,441, individual first.

## The SMSF contribution interface for WP-D
Agreed with WP-D's `retirement_contributions` (their migration 0304) and `SmsfDestinationProvider`. `lib/services/smsfContributionDestination.ts`:
- `listSmsfContributionDestinations(userId, client)` returns `{ fundId, retirementAccountId, fundName, currency, memberIds }[]`, the same shape WP-D's default provider returns.
- `loadSmsfContributionHistory(userId, retirementAccountId, client)` READS ledger rows with `destination_kind = 'smsf'` and `status = 'active'` (owner only) and lists them in the SMSF report. It never writes, and it never adds the fund account's contribution columns on top: the report totals stay on those columns, which WP-D derives from the ledger, so nothing is counted twice (tested with and without the derived column). Until 0304 is applied the history is `unavailable` and the screen shows nothing extra.
`wpCSmsfContributionInterface.test.ts` (5).
