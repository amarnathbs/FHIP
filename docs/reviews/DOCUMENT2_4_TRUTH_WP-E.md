| PO comment | "Now I tried to update as normal loan ... Same error message so I cant update any liability now" (screenshots on app.financialhealthplatform.com, Liabilities > Add/Edit) |
| What the screenshots actually show | The red line under Save reads: `new row for relation "liabilities" violates check constraint "chk_liabilities_masked_identifier" - try Save again.` The field "Card / Account Number (masked)" holds 300017434 (9 digits) in the first and 3000017434 (10 digits) in the second. | Current UI / API / service / DB | UI: grid field `masked_identifier` (lib/grid/configs.ts) is a free text box with no guidance. API: lib/validation/liability.ts allowed any string up to 32 chars. Service: registry.save/update pass it through. DB: migration 0096 CHECK `chk_liabilities_masked_identifier` (`masked_identifier !~ '[0-9]{7,}'`) refuses a run of 7+ digits by design (a full card/account number is never stored). The database was the first thing to answer, and its raw message went to the user as HTTP 400 and the grid then said "try Save again" with the same entry. |
| Owner model traced | UI OWNER_OPTIONS = Zod OWNER_VALUES = migration 0004 owner CHECK = self / spouse / joint / child / family_trust / company / smsf / other. `related_partner` appears nowhere in code or migrations. Consistent end to end; owner is not the cause and the DB enum was not widened. |
| Root cause | Field label invites an account number; nothing said "last 4 digits only"; nothing validated before send; the API did not validate the rule; the database constraint message leaked to the user. A person who types a full number once sees the same failure for every liability type because the form keeps the entry, hence "I can't update any liability". |
| Regression? | Not an owner-before-upload regression. The rule dates from migration 0096 (FDH-10). What is recent is the field being visible and editable (WP-07 G7). Classified: latent UX/validation defect, severity High (blocks saving any liability edit that contains the number). |
| Fix | lib/validation/maskedIdentifier.ts (single rule + one plain sentence); Zod superRefine on masked_identifier (POST and PATCH); lib/api.ts `badField`; both liability routes translate the DB rule if ever first to answer (422 with `fields`); grid: field `validate` + help text, pre-submit check, API `fields` messages shown by field name, a field-named 422 is not auto-retried and no longer says "try Save again". No migration. No DB change. |
