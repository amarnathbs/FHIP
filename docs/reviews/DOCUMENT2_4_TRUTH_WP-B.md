## Case classification used by the fix (what a resolution really needs)

| Case type | Real need | File required? | Path when the file is gone |
|---|---|---|---|
| `owner_unmatched`, `owner_mismatch`, `joint_holding_allocation_required` | owner selection | no | resolve in place (`PATCH /accounts/[id]/owner`) |
| `ambiguous_instrument` | instrument resolution | only to APPLY the choice | save the choice now (it is kept on the case); applying it needs a replacement copy, said plainly |
| `transaction_unclassified` | transaction classification | no | resolve in place |
| `cross_source_conflict`, `cross_source_review_required` | source conflict choice | no | resolve in place |
| `document_password_required` | password + reprocess | yes | `Upload replacement copy` (+ password) or `Close stale case` when the person no longer has the file |
| `unsupported_document`, `document_corrupt`, `parse_incomplete` | corrected file | yes | `Discard` (existing) / `Upload replacement copy` |
| `transaction_missing_from_restatement`, `other`, informational | none | no | acknowledge-only, never a dead button |
| any other open case on a document with no stored file and no retained data | information no longer exists | n/a | governed `Close stale case` with an audit trail; history is kept (status `resolved`, method `user_closed_stale_case`), never deleted |
