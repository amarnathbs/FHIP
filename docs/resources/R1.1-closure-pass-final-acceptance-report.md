## C. Closure Changes Made

1. **Analyst role added** to `resource_user_roles`'s CHECK constraint (`0033`, patched live via `0035`), architected conservatively per the brief: holds no content-workflow capability. `private.is_resource_staff()` was redefined to explicitly exclude `analyst` (it previously granted broad staff read access to *any* active role row, which would have wrongly included Analyst — caught and fixed during this reconciliation, before it was ever live). A new `private.is_resource_analyst()` predicate was added for a future analytics surface to attach a policy to; nothing grants access based on it yet.
2. **Seed (`0034`) reconciled**: the five seeded categories are genuine top-level taxonomy drawn directly from the brief's own §24 eventual-category list, not test fixtures — documentation was corrected from "test-only categories" to "initial foundational taxonomy seed." They were kept, not removed.
3. **Migrations applied to DEV** (`0033`, `0034`, `0035`, `0036`) — see §D.
4. **Two genuine defects found via live testing and fixed:**
   - `private.is_resource_staff()` incorrectly included `analyst` in its broad staff-access check before the closure-pass reconciliation caught it (fixed in the same edit that added the role, before any live exposure).
   - **`anon` was never granted `EXECUTE` on `private.is_resource_staff` or `private.can_manage_resources`.** This broke *every* anonymous read of `resource_posts` outright (fail-closed, `permission denied for function is_resource_staff`, not a security leak) because Postgres requires the querying role to hold `EXECUTE` on every function referenced in *any* RLS policy on a table it queries, even a policy that ultimately evaluates false for that role. Found live, fixed via `0036`, re-verified live (see §I).
5. **Database test suite rewritten** from graceful-skip-if-schema-absent to genuine fail-closed live tests (`beforeAll` now throws if the schema is missing, per §10 of the brief) — expanded from 8 assertions to 23, covering every mandatory item in §36 (see §I/§J/§K/§L).
6. **Documentation corrected**: table count ("15" → accurate "20, broken down 9+6+5"), RLS matrix extended with an Analyst column, seed language corrected.
7. **TypeScript types and permission helpers extended** with `analyst`/`isResourceAnalyst()`, `isResourceStaff()` corrected to mirror the DB-side exclusion exactly.
8. **`npm run build` run** (was deferred at the end of R1.1 proper; mandatory here, see §N).

## G. Analyst Reconciliation

Added as `resource_user_roles`'s sixth role value. `private.is_resource_staff()` — the function every draft-visibility and content-editing RLS policy calls — was explicitly redefined to check for the five *content-workflow* roles only, deliberately excluding `analyst`, so holding the Analyst role grants **zero** additional table access beyond reading one's own `resource_user_roles` row (the same self-read policy every role gets). A separate `private.is_resource_analyst()` predicate exists as a ready-made hook for a future analytics-table migration; no table or policy references it yet, because no analytics surface exists in R1.1. All five "Analyst cannot..." requirements from the closure brief's §26 were live-tested and passed (§J).
