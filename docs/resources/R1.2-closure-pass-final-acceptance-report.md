**Enter/Space control activation — tool limitation, not an app defect**: pressing Enter or Space on a focused native `<button>` ("Clear Filters") and a focused native link did not trigger their default click behavior through the Browser pane's synthetic `key` action, on **both** a `<button>` and an `<a>` element (i.e., the failure is systemic across element types, not specific to one control). Enter-activates-focused-button and Enter-activates-focused-link are unmodified, standard HTML/browser behavior — nothing in the FHIP codebase implements or could break this — and dispatching the identical action via `element.click()` (bypassing only the synthetic-keypress step) worked immediately and correctly in both cases. This was concluded to be a limitation of this specific automation tool's synthetic key-event simulation in this environment, not a genuine keyboard-accessibility defect, and is recorded here as **TOOL LIMITATION — verified indirectly via handler dispatch, not a controllable app-level defect** rather than fabricated as either a live PASS or a defect.
