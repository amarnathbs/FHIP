## H. @GKTC Video Architecture

YouTube remains the only video host. `parseYouTubeVideoId()` (`lib/resources/video/youtube.ts`) never makes an outbound request — pure `URL` parsing, protocol-gated to `http(s)` only. The embed component (`YouTubeEmbed.tsx`) takes only a `videoId` prop — there is no code path through which an arbitrary iframe URL can reach the DOM. No YouTube API key, no MP4 upload, no transcoding, no automatic channel sync anywhere. "Hosted on @GKTC YouTube" / "Watch on YouTube" copy appears in the list empty-state, the new-video form, the editor, and the preview.

## I. Video List

Server-paginated (25/page, clamped 100 max, reusing R1.2's `ResourcePagination`), searches title/YouTube ID, filters by status/jurisdiction/compliance. List query selects metadata only — verified live and by a dedicated unit test that no returned item carries `transcript`/`chapters` (spec §124).

## J. Video Editor

Fields: title, slug, excerpt, duration, YouTube publish date, thumbnail URL (defaults to the YouTube-derived `hqdefault.jpg`, overridable), @GKTC channel handle/URL, embed-enabled toggle, transcript (plain textarea, manual paste only), chapters (add/move-up/move-down/delete, each with `aria-label`, timestamp format validated). No `content_blocks` body — Video's spec §17 field list has no long-form structured content, so this was deliberately omitted rather than force-fit into the Article block model.

## K. Video Preview

`/admin/resources/videos/[id]/preview`, admin-only. Embed URL is always `buildYouTubeEmbedUrl(videoId)` — derived, never accepted raw. iframe carries a meaningful `title` ("@GKTC video preview: {title}"). An invalid/missing video renders the exact required message: "This YouTube video cannot be previewed. Check the Video ID or URL." — never an iframe.

## L. Glossary Management

Term → `title`, Short Definition → `excerpt`, Detailed Explanation/Example → `content_blocks` (R1.3's `BlockEditor`, unmodified — optional per spec §28), Aliases → new `aliases text[]` column with a chip editor, Related Terms → `resource_related_content` reused as-is (self-reference/duplicate-pair already blocked by its own DB constraints). Duplicate protection: an exact case-insensitive match hard-rejects the save; a substring match warns (debounced check-as-you-type) without blocking.

## M. FAQ Management

Question + required Short Answer + optional structured Expanded Answer (`answer_blocks`), Category (new FK to `resource_categories`), Jurisdiction, Compliance classification (new column, informational only — FAQs have no workflow RPC), Active toggle. Linking via `resource_post_faqs` with duplicate-relationship rejection and per-post `sort_order` (already existed). Delete is refused server-side while any link exists (`deleteFaqIfUnlinked`) — the UI surfaces the linked-content count before offering delete, and prefers "mark inactive."

## N. Money Update Management

Structured starter template (`starterTemplateForMoneyUpdate()`) pre-populates What Happened / Why It Matters / Who May Be Affected / Financial Health Impact / How FHIP Can Help as `content_blocks` headings — editable, with room for additional blocks after. Event Date and Affected Audience are new dedicated columns (not squeezed into content_blocks, since Event Date needs to be a real sortable/filterable list column). Freshness defaults to `time_sensitive`; review-readiness requires either a next-review date or an expiry date. GREEN content classified as GREEN gets a non-blocking editorial nudge if it looks like it might be regulatory/current-affairs (no automatic classification logic was invented, per spec §47's explicit prohibition).

## O. Money Update Templates

`content_type = 'money_update_template'`, own starter template with guidance placeholder text instead of blank paragraphs. "Create Update from Template" (`/api/admin/resources/money-updates/from-template`) copies `content_blocks`/jurisdiction/compliance/category/tags into a brand-new draft with its own id/slug and never mutates the template — verified live via unit test.

## P. Sources

Minimal implementation as instructed (spec §50): a picker over existing `resource_sources` plus an inline "Add a Source" mini-form (name, document title, URL, type, publication date, public flag). No standalone Source Library UI was built. URL validation uses `new URL()` + protocol check (https-only), same technique as the YouTube parser — `javascript:`/`data:` rejected, verified live and by unit test.

## Q. Save / Autosave

Video, Glossary, Money Update reuse R1.3's exact autosave pattern (2.5s debounce after a real change, manual Save always available, 4-state `SaveStatus`). FAQ is explicit-Save-only, no autosave — a deliberate, documented choice (spec §56 explicitly permits this for small forms; "reliability matters more"). Stale-write protection: Video/Glossary/Money Update reuse R1.3's `updated_at`-gated optimistic concurrency via `updateResourceDraft`; FAQ has its own `updateFaq()` using the identical pattern against `resource_faqs.updated_at` — live-verified: a save using a stale `updated_at` returns 409/`conflict`, the newer content is not overwritten.

## R. Validation

Video: `lib/resources/video/validation.ts` (its own module — see §AB defect). Glossary: `lib/resources/glossary/validation.ts` (content_blocks optional). FAQ: `lib/resources/faq/validation.ts` (question + short answer required). Money Update: `lib/resources/money-update/validation.ts` (event_date + review-or-expiry required for a real update, not for a template).

## S. Workflow

Video, Glossary, Money Update all route through the unmodified R1.1 `transition_resource_post_status` RPC — no second workflow implementation exists anywhere in R1.4 (verified: each `[id]/workflow/route.ts` is a thin, near-identical wrapper). FAQ has no workflow (not a resource_post, per spec §32/§54) — only active/inactive + audit columns.

## T. Revision History
