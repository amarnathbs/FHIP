## Decisions and things the PO should know

1. Admin has no home page, so first-level Admin tools return to the Dashboard; `/admin/resources/analytics` also returns to the Dashboard (an Analyst-only caller cannot enter the Resources dashboard).
2. Where no country is known (Admin lists, public Resources pages, legal pages, account closure) the app-wide Australian fallback `dd/mm/yyyy` is used; India-context screens (Reference Data Quality, Look-Through, Market Index, Investment Intelligence notes) use `dd-mm-yyyy`. Money Updates, Resources lists and public Resources dates changed from "20 Aug 2026" to `20/08/2026`: confirm that is what you want for the public Resources site.
3. The upload file-layout dropdown still shows a sample like `2024-01-31` beside the plain-words label "Year first (year, month, day)": it describes the person's own file. Say if even that must go.
4. A typed `2026-08-20` is rejected by the new date fields (day-first only, by design); an operator pasting an ISO date must retype it.
5. The marketing "Last updated" line on the legal pages is today's date (as before), now day-first.
6. Cron and operator API routes now say "an ISO 8601 calendar date" instead of printing the pattern; they still accept ISO.
7. When Mission B's branch merges, any new `page.tsx` it adds without `PageBackLink` fails `pageBackLinkGuard`, and any new `type="date"` or `YYYY-MM-DD` text fails the date guard: that is intended. `components/resources/editor/FormField.tsx` (new `DateTextField`) and the four editors' date lines are the only Resources-editor lines touched, so a trivial merge conflict is possible there.
8. The NAV2 branch `feat/nav2-stage2-datefmt-20261005` was not merged; `components/ui/DateInput.tsx` is byte-identical to its copy, and my guard has a different file name from its two date tests, so both can coexist after that branch lands (their allow-lists name files that only exist there).
9. `role="menu"` semantics remain on the sidebar dropdowns (the e2e specs select them by role). axe is clean, but a menu role promises arrow-key behaviour that is not implemented; the lower-risk follow-up is to drop the menu roles and update the three e2e specs, which needs DEV credentials to verify.
10. The `node_modules` entry in this worktree is a junction to the main checkout; remove it with `rmdir` (not a recursive delete) before removing the worktree.
