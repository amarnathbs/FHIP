## D. Defects found during this mission

1. **AMC/Fund House concentration was silently non-functional against all real data** (Finding #9). `lib/services/investment-intelligence/r5Repository.ts` hardcoded `amcId`/`amcName` to `null` on every position; `calculateAmcConcentration()` therefore always returned `status:'unavailable'`. Pre-existing (predates the `84debc5` pie-chart UI commit that this matrix's source mission cited). **Fixed this pass** (commit `e9c9d2f`) by joining through `ii_scheme_master`. Verified against real DEV data (3/3 real held instruments resolve a correct AMC name via the new join).
2. **Tax & Cost error messages leaked raw internal identifiers** (Finding #16). `tax/summary`, `tax/lots`, `tax/redemption-simulation` routes interpolated a caught engine error's `.message` (which embeds `sourceEventId`/`lotId`/`instrumentKey`) directly into the user-facing response. **Fixed this pass** (commit `e9c9d2f`): raw detail now server-log-only; client gets a clean, generic message.
3. **Migration `0227`'s own header comment and its originating commit message are stale/incorrect relative to actual DEV state.** Both explicitly claim "NOT YET APPLIED to DEV/production"; a direct negative-control insert proved the constraint is in fact live on DEV. Not a code defect, but a documentation-vs-reality gap worth flagging: **do not infer database state from a migration file's or commit's own claim** — verify directly, as this pass did.
4. **`components/pc5/ResolutionDetailClient.tsx` still calls `new Date(...).toLocaleString()` directly**, bypassing the canonical date formatter (Finding #8/#19). Confirmed **orphaned/unreachable** in the live app (no page links to it since the 2026-09-28 repoint of `/investment-intelligence/resolutions` to `ResolutionHistoryClient.tsx`) — real defect, zero live user impact. Not fixed in this pass (fixing dead code was judged lower value than the two defects above); flagged for a dedicated PC5-UI-removal pass.
5. **`ambiguous_instrument` and every `cross_source_*` discrepancy type have no real Fix action** (Acknowledge/Dismiss only) — confirmed still true, explicitly disclosed in-code (zero real production occurrences as of the check date), not silently dropped, but not closed either per Finding #10's own global rule. The same applies to roughly 11 further discrepancy types that were not separately called out in code comments.
6. **Production database migration status for `0227` (the `owner_mismatch`/`joint_holding_allocation_required` widening) is unconfirmed.** Cannot be tested directly under this pass's read-only production access; needs an operator/PO check of the production migration ledger.
7. **A known, previously-found, still-open defect** (not discovered fresh in this pass, re-confirmed still unaddressed): a fully-redeemed (zero-unit) investment position can never be re-evaluated/certified (`recertifyPosition`/`evaluatePositionAndCertify` silently no-ops). Recorded in project memory from the 2026-09-28 walkthrough; no commit in the current `git log` touches this.
8. **No standing regression test exists yet for Finding #6's global "no internal id in user-facing text" rule** across the whole Investment Intelligence surface (the specific Portfolio Truth instance is fixed and was grep-audited clean, but there is no automated guard preventing a future regression class-wide).
