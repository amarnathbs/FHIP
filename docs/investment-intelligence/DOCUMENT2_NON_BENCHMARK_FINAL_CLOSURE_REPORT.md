## D. New defects found during this mission

1. **`resolveScheme()`'s own documented AMC filter was never implemented** (Finding #3/#10, `schemeResolution.ts`). Two different fund houses publishing an identically-normalised scheme name/plan/option were spuriously reported ambiguous, or worse, could silently cross-match to the wrong AMC's instrument. **Fixed this pass.** Additive fix (a `null` existing AMC still matches any AMC) — cannot introduce a new false negative for an already-working match.
2. **The controlled alias-map mechanism (`ii_scheme_alias_map`, `resolveScheme()` step 5) was structurally unreachable for resolving a genuine ambiguity** — the function returns `'ambiguous'` and stops at the first step (ISIN/AMFI/name+plan+option) that finds >1 candidate, never falling through to the alias-map step. This is why `ambiguous_instrument` could never have been fixed by adding alias rows alone; the real fix needed an explicit pre-`resolveScheme()` override consultation, which this pass built.
3. **The prior pass's own matrix claim that `transaction_unclassified` "has a classification path per `documentProcessing.ts`'s wiring" was inaccurate** — that wiring is the system's own initial parse-time classification, never a user-facing re-classification action. No such action existed before this pass. This is a more consequential gap than most of the disclosed ones: a material instance is a genuine certification blocker.
4. **`ambiguousInstrumentResolution.ts`'s first draft this pass queried `ii_reconciliation_cases.superseded_by_id`, a column that does not exist on that table** (it exists only on unrelated tables `ii_prices_nav`/`ii_benchmark_series`/`ii_review_items`). This would have 400'd against real production PostgREST exactly as it failed the test fixture. **Caught by this pass's own regression suite before reaching `origin/main`, fixed to use the table's real supersession mechanism** (`discrepancy_details.amendsCaseId`). Recorded per this project's own standing lesson that negative controls/regression suites — not manual review alone — are what catch this class of defect.
5. **A genuinely, independently confirmed real repository dependency-declaration gap**: even a clean `npm ci` install cannot resolve `stripe`'s own bundled TypeScript declarations (`TS7016` across 3 files). This answers the prior pass's own open question from a clean checkout: it is **not** merely "that worktree hadn't installed" — it reproduces from a genuinely fresh install. Classified as a real, separate repository/build defect, out of Document2's scope, not fixed here, flagged for a dedicated fix.
6. **`cross_source_conflict`/`cross_source_review_required` cases raised through the live `/api/investment-intelligence/positions/manual` manual-entry path (`manualImporter.ts`) did not record which transaction they were about**, unlike the CAS/KFintech statement path — meaning the new resolution route would silently show no action for this path's cases. **Fixed this pass**: the case is now backfilled with the real transaction id once it is known (DB-generated, unlike the statement path's client-generated id).
