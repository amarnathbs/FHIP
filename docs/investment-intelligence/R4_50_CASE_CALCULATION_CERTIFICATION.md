# R4 — 50-Case Independent Calculation Certification

## Result: 50/50 PASS

Every case below compares a **production** result (computed by direct
import of `lib/engines/investment-intelligence/*.ts`, in
`tests/unit/iiR4Certification50Case.test.ts`) against an **independent**
result (computed from scratch in Python by
`scripts/ii_r4_independent_reconciliation.py`, which imports nothing from
production — see `R4_ORACLE_DESIGN` note below). Both sides consume the
identical input data from `scripts/ii-r4-certification/cases.json`,
generated by a pure, dependency-free, fixed-seed JS generator
(`scripts/ii-r4-certification/generate_cases.mjs`) that also imports
nothing from production.

**Tolerances were fixed before any case was run** (spec section 78):
currency `≤ ₹0.01`, NAV-derived/CAGR `≤ 0.000001`, XIRR `≤ 0.000001`,
TWRR `≤ 0.000001`, risk metrics `≤ 0.000001`, weights `≤ 0.000001`. No
tolerance was widened after seeing a result.

**Max variance by metric family** (all comfortably inside tolerance):

| Family | n | Max variance |
|---|---|---|
| cagr | 11 | 0 (exact) |
| xirr | 12 | 2.66e-8 |
| twrr | 11 | 0 (exact) |
| blendedBenchmark | 5 | 0 (exact) |
| activeReturn | 5 | 0 (exact) |
| riskBundle | 6 | 4.44e-16 (floating-point noise only) |

XIRR shows nonzero variance because production (safeguarded Newton) and
the oracle (pure bisection) are genuinely different iterative algorithms
converging to the same root from different paths — their residual
differences (max `2.66e-8`, over 30x tighter than the `1e-6` tolerance)
are exactly what independent numerical convergence looks like, not
evidence of disagreement. CAGR/TWRR/blended-benchmark/active-return are
closed-form (no iterative solve), so both implementations land on
bit-identical or near-bit-identical results.

## A real bug this process found before certification

`TC002` and `TC004` initially FAILED (production returned a nonzero
`cagr` field for an exactly-365-day period; the oracle correctly left it
`undefined` per the documented "> 365 days only" annualisation boundary).
Root cause: `cagr()` in `navReturn.ts` used a `years < 1` cutoff while the
underlying `pointToPointReturn()` used a stricter `actualDays > 365`
cutoff — an inconsistent boundary in two places, exactly the class of bug
spec section 18 warns against. Fixed by making `cagr()` a pure pass-through
of `pointToPointReturn()`'s own (single, authoritative) boundary decision.
Re-run: 50/50 PASS. See `git log` / `R4_IMPLEMENTATION_REPORT.md` for the
commit.

## Reproducing this certification

```
node scripts/ii-r4-certification/generate_cases.mjs
python scripts/ii_r4_independent_reconciliation.py scripts/ii-r4-certification/cases.json scripts/ii-r4-certification/oracle_results.json
npx vitest run tests/unit/iiR4Certification50Case.test.ts
```

The test fails (non-zero exit) if any case's variance exceeds tolerance,
so this is a genuine CI-checkable gate, not a one-off manual comparison.
